# SmartHome — בית חכם

אפליקציית ניהול משק בית משפחתי, מסונכרנת בזמן אמת בין כל בני המשפחה.
כל בן בית רואה מיד את מה שהאחרים עשו — משימה שבוצעה, פריט שנקנה, אירוע
שנוסף — בלי לרענן את הדף. הממשק בעברית ו-RTL מלא.

המערכת בנויה סביב **בידוד מוחלט בין משקי בית**: כל משפחה רואה אך ורק את
הנתונים שלה, והבידוד נאכף בשכבת בסיס הנתונים ולא בקוד הקונטרולרים.

---

## סטאק טכנולוגי

### שרת — `SmartHomeApi/`

| רכיב | בפועל |
|---|---|
| Framework | ASP.NET Core Web API, .NET 8 |
| בסיס נתונים | SQLite דרך EF Core 8 (`smarthome.db`) |
| אימות | ASP.NET Core Identity מבוסס **עוגיות** (מייל + סיסמה) |
| זמן אמת | SignalR — Hub בכתובת `/hubs/smarthome` |
| תמונות | Cloudinary (`CloudinaryDotNet`) |
| מייל | MailKit (SMTP, לאיפוס סיסמה) |
| אבטחת קלט | HtmlSanitizer — ניקוי HTML מעורך הטקסט העשיר |
| תיעוד API | Swagger, בסביבת פיתוח בלבד |

### לקוח — `client/`

React 19 + Vite 6 + TypeScript 5.7 (strict, ללא `any`).
Zustand לניהול state, React Router 7 לניווט, Axios לקריאות, dayjs לתאריכים,
react-hot-toast להודעות, `@microsoft/signalr` לזמן אמת, ו-`vite-plugin-pwa`
ל-Service Worker.

### מוסכמות בין השרת ללקוח

- כל ה-JSON ב-camelCase, ו-enums מסודרים כמחרוזות.
- השרת מחזיר **DTOs בלבד**, לעולם לא ישויות.
- מזהי ישויות מוחזרים גם כ-`_id` (שריד מגרסה קודמת שה-client עדיין
  מסתמך עליה) וגם כ-`id` היכן שרלוונטי.
- שגיאות מוחזרות תמיד בגוף `{ "message": "..." }` בעברית, כולל 401 ו-403.

## המודולים המיושמים

1. **אימות משתמשים** — הרשמה, כניסה ויציאה במייל וסיסמה, איפוס סיסמה
   בקישור שנשלח במייל (תקף 30 דקות, מוגבל ל-3 בקשות לשעה). משתמש חדש
   מצטרף לבית קיים בקוד הזמנה או פותח בית חדש, וממתין לאישור מנהל.

2. **דשבורד ראשי** — מסך הבית: התראות שדורשות תשומת לב, סטטיסטיקות
   משימות/קניות/אירועים, קיצורי דרך לכל המודולים, ושלושת המובילים בנקודות.

3. **משימות בית** — יצירה, שיוך לבן משפחה, עדיפות ותאריך יעד. שינוי סטטוס
   ל"בוצע" מזכה את המבצע בנקודות אוטומטית לפי העדיפות. תיאור המשימה עובר
   ניקוי HTML בשרת.

4. **רשימת קניות** — הוספה, סימון "נקנה" ומחיקה, עם עדכון מיידי אצל כל
   בני הבית.

5. **לוח שנה ואירועים** — אירועים עם תאריך, תיאור, צבע וסימון "כל היום".

6. **מעקב מתנות** — למי, לאיזה אירוע, רשימת רעיונות וסימון "נקנה". מתנה
   ניתנת לקישור לאירוע בלוח השנה. **אין ולא יהיה שדה סכום או המלצת מחיר**
   — לא במודל, לא ב-API ולא בממשק.

7. **ניהול תקציב** — הכנסות והוצאות עם קטגוריה ותאריך, סינון לפי חודש,
   וסיכום הכנסות/הוצאות/יתרה.

8. **מלאי מזון** — פריטים מקובצים לפי קטגוריה, עם כמות, יחידת מידה, מיקום
   וכמות מינימלית. עדכון כמות מהיר מכפתורי +/- ברשימה.

9. **תיק רפואי** — רשומות לכל בן משפחה (תור, תרופה, חיסון, הערה) עם רופא,
   מרפאה ותאריך תור הבא.

10. **ניהול רכב** — רכבי הבית עם מספר רישוי, שנה, סוג דלק, טיפול אחרון
    והבא, ותאריכי ביטוח וטסט. הרכב שהטסט שלו הקרוב ביותר מוצג ראשון.

11. **גמיפיקציה** — לוח מובילים לכל בני הבית לפי נקודות. נקודות נצברות
    אוטומטית מהשלמת משימות: דחוף 30, רגיל 20, יכול לחכות 10. תגי סף לפי
    צבירה, ואיפוס נקודות לכולם בידי מנהל.

12. **מערכת התראות** — `GET api/notifications` מרכיב את כל מה שדורש תשומת
    לב ומחזיר ממוין לפי קרבה: אירוע בשבוע הקרוב, מתנה שטרם נקנתה לאירוע
    מתקרב, פריט מלאי שירד לסף, תור רפואי קרוב, וטסט או ביטוח שפגים בחודש
    הקרוב. כל התראה מסומנת ברמת דחיפות — `info`, `warning` או `urgent`.

בנוסף קיימים במערכת **ניהול חברי הבית** (אישור, חסימה, שינוי תפקיד ומחיקה,
למנהל בלבד) ו**מונה מבקרים ומשתמשים מחוברים**.

### עדכון בזמן אמת — חוק ברזל

כל יצירה, עדכון ומחיקה משדרים אירוע SignalR לכל בני הבית, וכל דף מאזין
לאירועים שלו ומעדכן את המסך בלי רענון. הנקודות בלוח המובילים מתעדכנות כך
גם הן, ברגע שמישהו אחר סיים משימה.

## הרצה מקומית

דרישות: .NET 8 SDK ו-Node.js 18 ומעלה.

### שרת

```bash
cd SmartHomeApi
dotnet run
```

השרת עולה על `http://localhost:5263`. המיגרציות מורצות אוטומטית בעלייה,
ובסיס הנתונים נזרע בתפקידים, משק בית לדוגמה ומשתמש מנהל. Swagger זמין
בפיתוח בכתובת `/swagger`.

### לקוח

```bash
cd client
npm install
npm run dev
```

הלקוח עולה על `http://localhost:5173`. הכתובת הזו תמיד מותרת ב-CORS של
השרת, כולל שליחת עוגיות. כתובות נוספות — למשל של סביבת ייצור — נקראות
מ-`Cors:AllowedOrigins` ואפשר להוסיף אותן כמשתנה סביבה
(`Cors__AllowedOrigins__0`) בלי לגעת בקוד.

### סודות

**אין שום סוד בקוד או ב-`appsettings.json`.** כל המפתחות נקראים מ-User
Secrets:

```bash
cd SmartHomeApi
dotnet user-secrets set "Cloudinary:CloudName" "..."
dotnet user-secrets set "Cloudinary:ApiKey"    "..."
dotnet user-secrets set "Cloudinary:ApiSecret" "..."
dotnet user-secrets set "Email:Host"     "smtp.gmail.com"
dotnet user-secrets set "Email:Port"     "587"
dotnet user-secrets set "Email:Username" "..."
dotnet user-secrets set "Email:Password" "..."
```

יוצא דופן אחד הוא סיסמת משתמש המנהל הראשוני, שנקראת מ-`appsettings.Local.json`.
הקובץ מוחרג מ-Git; העתק את `appsettings.Local.example.json` ומלא סיסמה.
בלי סיסמה כזו המנהל הראשוני פשוט לא נוצר, והשרת יעלה כרגיל עם אזהרה ביומן.

השירותים קוראים את ההגדרות בזמן השימוש ולא בעלייה, ולכן המערכת עובדת גם
כשאין Cloudinary או SMTP מוגדרים — רק הפעולות שתלויות בהם ייכשלו.

## פריסה

השרת נארז כקונטיינר: `SmartHomeApi/Dockerfile` בונה בשני שלבים ומריץ
`dotnet SmartHomeApi.dll`. הקשר הבנייה הוא תיקיית `SmartHomeApi` עצמה ולא
שורש המאגר. הלקוח נבנה ב-`npm run build` ומוגש כאתר סטטי מתוך `client/dist`.

הקוד מותאם לאירוח מאחורי פרוקסי שמסיים HTTPS:

- מאזין לפורט שמוזרק במשתנה הסביבה `PORT`, על כל הממשקים.
- קורא את כותרות `X-Forwarded-For` ו-`X-Forwarded-Proto`.
- מחוץ לפיתוח, עוגיית ההזדהות ועוגיית ה-Session מסומנות `SameSite=None`
  ו-`Secure`, כי הלקוח וה-API יושבים על דומיינים נפרדים.

משתני סביבה שצריך להגדיר בשירות האירוח: `Cors__AllowedOrigins__0` עם כתובת
הלקוח, `ClientBaseUrl`, `Seed__ManagerPassword`, וכן `Cloudinary__*`
ו-`Email__*`. בלקוח מגדירים `VITE_API_URL` עם כתובת ה-API — origin בלבד,
בלי `/api` ובלי סלאש בסוף.

## מגבלות ופערים ידועים

רשימה כנה של מה שלא מומש, ולמה.

### מסד הנתונים

- **SQLite כקובץ מקומי.** הפרסה על שירות עם מערכת קבצים זמנית — למשל
  Render בתוכנית החינמית — תמחק את כל הנתונים בכל redeploy או restart.
  מעבר לייצור אמיתי מחייב בסיס נתונים מנוהל (PostgreSQL או SQL Server)
  ואחסון קבוע.
- **מפתחות ההצפנה של העוגיות נשמרים בתוך הקונטיינר.** הם נוצרים מחדש בכל
  עלייה, וכל עוגיות ההתחברות הקיימות נפסלות — כלומר כל המשתמשים מנותקים
  בכל redeploy או restart. פתרון קבוע דורש התמדה של מפתחות ה-Data
  Protection באחסון משותף.

### אימות

- **אין כניסה עם Google.** המימוש בפועל הוא מייל וסיסמה עם עוגיית Identity.
  החבילה `@react-oauth/google` מותקנת בלקוח אך אינה מחוברת לשום מסך. זהו
  פער מול מפרט הפרויקט.
- העוגייה תקפה לשעתיים עם הארכה מתגלגלת, ולכן שרת שמופעל מחדש לא מנתק
  משתמשים, אבל חוסר פעילות ממושך כן.

### התראות

- **התראות מחושבות בזמן טעינה בלבד.** אין שירות רקע, אין דחיפה ואין מייל.
  התראה מתגלה רק כשנכנסים לאפליקציה וטוענים את הדשבורד.
- **אין התראת תקציב.** המפרט מבקש התראה בהגעה ל-80% מהתקרה, אבל למודל
  התקציב אין שדה תקרה כלל — יש רק סכום, סוג, קטגוריה ותאריך. בלי תקרה אין
  ממה לגזור אחוז ניצול. הרחבה זו דורשת קודם מודל תקרות חודשיות לקטגוריה.
- **אין התראת תרופות יומית.** היא דורשת תזמון בשעה קבועה מדי יום, ולא
  ניתנת למימוש במודל שמחושב בכניסה לאפליקציה. מהמודול הרפואי נכללים תורים
  קרובים בלבד.
- אין סימון "נקרא" ואין מחיקת התראה — הרשימה מחושבת מחדש בכל קריאה.
- קיימים במערכת מודל וטבלה בשם `Notification` (כולל `IsRead` ו-`ScheduledFor`)
  שאינם בשימוש. הם הבסיס המוכן להרחבה לשליחה יזומה.

### גמיפיקציה

- **איפוס הנקודות ידני בלבד** — כפתור למנהל. אין איפוס שבועי אוטומטי, כי
  אין בפרויקט תשתית משימות מתוזמנות.
- **אין תגים מיוחדים** כמו "מנקה השבוע" או "אלוף הקניות". קיימים רק תגי סף
  גנריים לפי סך הנקודות שנצברו.
- ביטול סימון "בוצע" במשימה אינו מחזיר את הנקודות שכבר נזקפו.

### אלבומי תמונות

- המודול קיים בשרת במלואו (`AlbumsController`, `PhotosController`, העלאה
  ל-Cloudinary) אבל **אין לו שום מסך בלקוח ואין לו route**. הוא נגיש רק
  דרך ה-API.

### שונות

- הדשבורד מציג את לוח המובילים אך אינו מאזין לאירועי הגמיפיקציה בזמן אמת,
  ולכן הנקודות שם מתעדכנות רק ברענון. דף לוח המובילים עצמו כן מתעדכן חי.
- חלק מהתאריכים חוזרים מה-API בלי סיומת אזור זמן וחלק עם `Z`. בתוך מודול
  ההתראות הוסדר לאחידות, אבל אי-העקביות עדיין קיימת במקומות אחרים.
- טקסטים למשתמש מפוזרים בין הקומפוננטות ואינם מרוכזים בקובץ אחד.

## כללים שאסור לשבור

1. **בידוד משקי בית.** כל ישות משפחתית מממשת `IHouseholdOwned`, ו-Global
   Query Filter ב-`ApplicationDbContext` מסנן אוטומטית לפי משק הבית של
   המשתמש המחובר. בלי משתמש מחובר לא מוחזר דבר.
2. **עדכון בזמן אמת.** כל פעולה נשמרת מיד, שומרת מי ביצע ומתי, ומשודרת
   לכל בני הבית.
3. **DTOs בלבד** בתשובות ה-API, לעולם לא ישויות.
4. **אין המלצות סכום במתנות.** לעולם.
5. **TypeScript strict**, בלי `any`, בלי לוגיקה עסקית בקומפוננטות.
6. **סודות ב-User Secrets בלבד.**
